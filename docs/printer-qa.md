# 热敏打印机项目开发者 Q&A（ESP32-S3 + EM5823H + Mac）

本文档整理自项目重启初期的架构与技术原理讨论，帮助快速理解“为什么这样设计”以及“如何高效调试”。

---

### Q1：ESP32-S3、Mac（MacBook / Mac mini）、打印机三者是什么关系？
可以把整套系统理解成“厨房出单”：
* **优库 EM5823H 打印机**：纯硬件执行器，没有 Wi‑Fi，不认识网页和 UTF‑8 中文，只认串口（UART TX/RX/RTS）发来的 ESC/POS 二进制字节。
* **ESP32-S3（微雪开发板）**：插在打印机旁边的“传话筒 / 透传管道”。一边通过 Wi‑Fi 轮询 Mac 后端的打印队列，一边通过串口把 1-bit 点阵分片喂给打印机。**ESP32 不做排版、不做图片算法**，烧录一次稳定固件后几乎不需要再改。
* **MacBook / Mac mini**：真正的“大脑 + 美工”。负责数据库（Todo / 留言 / 队列）、HTML 排版、图像处理（Gamma + 抖动）以及提供浏览器预览和 MCP 接口。

### Q2：为什么先不用 E-ink（墨水屏）时需要调整固件？
原仓库的 [firmware/src/main.cpp](file:///Users/zhuanzmima0000/tinkering/printer_todo/firmware/src/main.cpp) 是为“墨水屏 + 热敏打印机”双设备设计的，开机会分配墨水屏缓存并定期拉图刷新。先只测打印机时，需要跳过 E-ink 初始化与拉图逻辑，只保留心跳（`sendHeartbeat`）和打印队列轮询（`pollPrintQueue`），避免无屏幕时报错或阻塞。

### Q3：什么是 ESC/POS？为什么我们只需要 1～2 条指令？
* **ESC/POS** 是爱普生制定的热敏小票机通用指令标准（绝大多数 58mm/80mm 打印机都兼容），命令通常以不可见控制字符 `ESC`（`0x1B`）或 `GS`（`0x1D`）开头。
* 传统驱动库（如 `python-escpos`）之所以庞大，是因为要兼容钱箱、切刀、条码、多国字符集和各种接口。
* 而在**全光栅化方案**中，字体、字号、居中、边框全部在 Mac 画图时完成了，打印机只需要听懂两条指令：
  1. **`GS v 0`（`0x1D 0x76 0x30`）**：逐行烧录 384px（48 字节/行）的 1-bit 黑白点阵；
  2. **走纸指令（如 `ESC d`）**：打完后多吐几行空白纸方便撕下。

---

### Q4：除了“全光栅化”，还有哪些打印方案？为什么选全光栅化？
| 方案 | 原理 | 局限性 / 优缺点 |
| :--- | :--- | :--- |
| **纯文本指令** | 发文字字节 + 排版指令，调用打印机内置字库 | 内置中文字库丑、不支持 Emoji 和自定义字体、必须转 GBK 极易乱码、排版难对齐 |
| **混合方案** | 标题/Logo 用图片，正文用内置字库 | 上下字体风格割裂，正文依然受限于内置字库 |
| **全光栅化（本项目）** | 整张小票在 Mac 渲染为 384px 宽的纯黑白点阵图再下发 | **所见即所得**：网页能排出来的字体、Emoji、复选框、表格都能一模一样打出来；代价是数据量较大，需 ESP32 分片 + `RTS` 流控发送 |

### Q5：JavaScript（Node/TS）与 Python 的打印库怎么选？
* `python-escpos` 确实长期维护且生态成熟，适合用 Python 写后端或主机直接 USB 连打印机。
* 本项目现有 `backend/`、`server/`、`pwa/` 全部基于 **TypeScript / Node.js**，且全光栅化方案中 ESC/POS 协议层极其简单（[printer-protocol.ts](file:///Users/zhuanzmima0000/tinkering/printer_todo/backend/src/printer-protocol.ts) 已用几行代码实现 `GS v 0`），真正的重头戏是**排版与图像处理**。
* 因此继续使用 **Node.js / TypeScript**（Puppeteer + JS 抖动算法，可参考 `receiptline` 与 `@point-of-sale/receipt-printer-encoder` 的实现）是最统一、最省事的选择。

### Q6：为什么“HTML + Puppeteer + Gamma 校正 + 抖动算法”是最强的？
这是一条 3 步流水线：
1. **HTML/CSS + Puppeteer（解决排版痛苦）**：
   在后台用无头 Chrome 渲染模板，锁定视口 `width: 384px, deviceScaleFactor: 1`（1 网页像素 = 1 打印机物理点），高度自适应。天然获得中文自动折行、Flex/Grid 布局、Emoji 渲染与系统字体能力，无需手动计算坐标。
2. **Gamma 校正（对抗热敏纸物理晕染）**：
   热敏头加热后热量会向四周扩散（Dot Gain），导致实际打印比屏幕更黑更粗。通过非线性曲线 $V_{out} = 255 \times (V_{in} / 255)^{1/\gamma}$（通常 $\gamma \approx 1.6 \sim 2.0$）提前提亮中间调，防止灰阶糊成黑块。
3. **误差扩散抖动 Dithering（在 1-bit 硬件上还原灰阶质感）**：
   热敏纸只能打纯黑（1）或纯白（0）。相比直接硬阈值（`< 128` 变黑）丢失全部细节，**Floyd-Steinberg / Atkinson 抖动**会把当前像素舍入产生的亮度误差按比例分摊给右边和下方的邻居像素，用黑点疏密模拟细腻灰阶。其中 **Atkinson 抖动**（仅扩散 75% 误差）高光与留白最干净，非常适合热敏纸。

### Q7：打印机没有自动切刀，每次撕纸都撕烂文字怎么办？
EM5823H 这类嵌入式 58mm 机芯通常只有出纸口上方的**手动锯齿撕纸条**，而打印头在锯齿下方约 1.5～2 cm 处。
**标准解法**：在每张小票模板最底部固定加上一段 **`✂ - - - - - -` 撕纸虚线 + 40～60px 纯白留空**（或打完后走纸 4 行），让正文完全越过锯齿后再停下，即可轻松对齐虚线撕下。

### Q8：SOTA 的低成本调试方式是什么？（如何告别“打出来像 shit 一样”和废纸？）
核心原则是**三层分离、浏览器零废纸闭环**：
1. **浏览器直接看“1-bit 抖动后”的最终像素图**：不要只看彩色/灰阶 HTML 原图，要在浏览器里把经过 Gamma + 抖动算法二值化后的真实点阵图 1:1 / 2:1 渲染出来，确认文字锐利、颗粒均匀、无糊块后再进入硬件测试。
2. **ESP32 只做无脑管道**：调通一次后不再因改模板而重编烧录固件。
3. **硬件校准只打 1 张“5cm 校准条”**：把不同字号、细线、灰度抖动块、二维码印在一张 5cm 小样上，一次性定好 Gamma 与加热浓度参数。
